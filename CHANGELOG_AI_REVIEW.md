# CHANGELOG_AI_REVIEW.md

Журнал доработок ядра приложения согласно ТЗ "исправить ядро приложения:
распознавание смет, генерацию документов, систему шаблонов, переменные,
скачивание файлов, UX-подсказки и валидацию данных".

## Итерация 1 (commit 545d8c6)
- Таблица `templates` + CRUD-роуты для библиотеки шаблонов.
- Единый эндпоинт `/api/documents/:objectId/generate` для всех типов документов.
- Поддержка CSV-смет, исправлена кодировка UTF-8.
- Новый статус `"Роботи виконані"` в воркфлоу объекта.
- Фронтенд подключён к новым эндпоинтам.

## Итерация 2 (commit fcc16ab)
- Исправлен баг парсера смет: при наличии нескольких листов/секций одной
  категории (материалы/работы) данные больше не теряются, а накапливаются.
- Система кастомных полей: таблицы `custom_fields`, `object_custom_field_values`,
  10 стартовых полей-сидов, CRUD `/api/custom-fields`, выдача `/api/variables`.
- Валидация переменных в DOCX-шаблонах: сканирование `word/document.xml`,
  поиск `{var}`/`{#loop}`, сверка с системными/кастомными переменными,
  подсказки "может, вы имели в виду..." через расстояние Левенштейна.
  Эндпоинты `/api/templates/:id/validate`, `/api/templates/:id/activate`.
- Исправлена авторизация при скачивании файлов: вместо `<a href>` теперь
  используется blob-fetch с Bearer-токеном (`ObjectDetail.tsx`, `Templates.tsx`).

## Итерация 3 (commit 821f04a)
- Валидация формы объекта (`ObjectForm.tsx`): телефон, email, длина имени,
  отсев тестовых значений, площадь, дата договора, тип работ.
- Кастомные поля рендерятся на форме объекта, группируются по `group_name`.
- Структурированная ошибка `{error, missingFields}` от `canGenerate()` —
  на фронте при блокировке кнопки показывается ссылка "Перейти до редагування".
- Подсказки (tooltip) на всех заблокированных кнопках генерации документов.
- Заметная кнопка "Редагувати об'єкт" + toast-уведомление после сохранения.

## Итерация 4 (commit b2afa91)
- Формулировки сообщений об AI-анализе приведены к точным русским строкам
  из ТЗ: "AI-анализ отключён. Используется базовый парсер.",
  "AI-анализ включён, но OPENAI_API_KEY/ANTHROPIC_API_KEY/AI_PROVIDER не
  настроен(а)." и формулировка для пустого результата распознавания.

## Итерация 5 (commit 5dca110)
- В `EstimateReview.tsx` добавлена кнопка "Подивитися сирий текст" —
  раскрывает `raw_text` распознанной смены прямо в карточке проверки.
- Добавлена возможность загрузить другой файл смены без необходимости
  сначала её подтверждать (ранее это было доступно только в подтверждённом
  состоянии).
- В `estimates.js`: при загрузке нового файла сметы для объекта теперь
  выставляется инкрементальный `version` и предыдущие версии помечаются
  `is_active = 0` (использует ранее добавленные, но не задействованные
  колонки `estimates.version`/`estimates.is_active`).

## Известные ограничения / не сделано в рамках этой сессии
- Не выполнен полный прогон сценариев A–F из части 15 ТЗ (требуется ручная
  проверка через UI с реальными файлами смет).
- Часть 9/10 ТЗ (дашборд, статистика, фильтры, "последнее действие") не
  проверялась повторно в этой сессии — требует отдельного аудита.
- README.md пока не обновлён под новые возможности (custom fields,
  валидация шаблонов, версии смет).
