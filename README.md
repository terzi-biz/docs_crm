# Terzi Docs CRM

Внутрішнє веб-застосування для автоматизації підготовки документів
(договір, кошторис, рахунок) для будівельної компанії.

## Стек

- Backend: Node.js + Express + SQLite (better-sqlite3)
- Frontend: React + TypeScript + Tailwind CSS (Vite)
- Генерація документів: docxtemplater (DOCX) + LibreOffice headless (DOCX → PDF)
- Розпізнавання кошторисів: `xlsx` / `pdf-parse` / `mammoth` + опціональний AI-аналізатор (OpenAI або Anthropic)

## Запуск (розробка)

```bash
npm install --workspaces
cp server/.env.example server/.env   # за потреби відредагувати
npm run dev:server   # http://localhost:4000
npm run dev:client   # http://localhost:5173 (проксує /api на 4000)
```

DOCX-шаблони (`server/src/templates/*.docx`) згенеровані з
`server/scripts/build_templates.py` (потребує `python-docx`) — їх можна
відредагувати безпосередньо в Word, зберігаючи теги `{tag}` для
docxtemplater.

## Як працює розпізнавання кошторису

1. Менеджер завантажує файл (XLSX/XLS/PDF/DOCX) на сторінці об'єкта.
2. `server/src/services/estimateParser.js` шукає секції "МАТЕРІАЛИ"/"РОБОТИ"
   за ключовими словами та евристично визначає назву/одиницю/кількість/ціну/суму
   в кожному рядку — без прив'язки до фіксованої структури таблиці (різні
   прораби готують кошторис по-різному).
3. Якщо впевненість парсера (`parser_confidence`) низька або файл нестандартний,
   і AI увімкнено — сирий текст передається в AI-аналізатор
   (`server/src/services/aiEstimateAnalyzer.js`), який повертає строго
   валідований (через `zod`) JSON у тому ж форматі.
4. Backend завжди перераховує суми (`quantity × price`), додає попередження
   при розбіжностях, і виставляє статус кошторису:
   `uploaded → parsed/pending_review → confirmed`.
5. Менеджер переглядає/править таблиці "Матеріали"/"Роботи" і натискає
   "Підтвердити кошторис" — лише після цього можна генерувати кошторис
   та повний пакет документів.

## Підтримувані формати кошторисів

- **XLSX / XLS** — читається через `xlsx`, найвища надійність розпізнавання.
- **PDF** — читається через `pdf-parse`; працює лише для текстових PDF.
  Скановані/зображення-PDF не розпізнаються — показується попередження
  "PDF виглядає як скан/зображення. Для автоматичного розпізнавання потрібен
  OCR або Excel-файл."
- **DOCX / DOC** — читається через `mammoth`.

## AI-аналіз кошторису (опціонально)

Вимикається/увімкається через `.env` (див. `server/.env.example`):

```
AI_ENABLED=true
AI_PROVIDER=openai      # або anthropic
OPENAI_API_KEY=...
ANTHROPIC_API_KEY=...
AI_MODEL=gpt-4o-mini     # або claude-sonnet-4-6
```

- `AI_ENABLED=false` (за замовчуванням) — система працює лише через
  звичайний парсер; при невпевненому розпізнаванні менеджер бачить
  попередження та править рядки вручну.
- `AI_ENABLED=true` — звичайний парсер запускається першим; AI
  викликається лише якщо його впевненість нижча порогу (0.6). AI ніколи
  не вигадує ціни/кількості — лише структурує наявний текст. Відповідь
  AI валідується схемою `zod`; некоректний JSON відхиляється і
  застосунок повертається до базового парсера з попередженням.
- Ніколи не комітьте `.env` — секрети зберігаються лише в змінних
  середовища, у репозиторії є тільки `server/.env.example`.

## Як формується кошторис-документ

Після підтвердження (`confirmed`) кошторис можна сформувати в DOCX/PDF
кнопкою "Створити кошторис" — генерується по шаблону
`server/src/templates/estimate.docx` з повним переліком матеріалів/робіт,
сумами та умовами оплати, як комерційний документ TERZI (а не технічна
таблиця).

## Примітка щодо PDF

Конвертація DOCX → PDF використовує `soffice --headless`. Якщо LibreOffice
у середовищі розгортання не може виконати рендеринг (відсутні
залежності/шрифти), система продовжує зберігати DOCX, а PDF-посилання
просто не з'являється для цього документа — це не блокує генерацію
пакету документів.

## Тестування парсера

```bash
cd server
npm run test:parser                          # парсить server/test-fixtures/sample-estimate.xlsx
npm run test:parser -- ./шлях/до/файлу.xlsx  # або власний файл
```

Команда виводить розпізнаний JSON (`materials`, `works`, суми,
`parser_confidence`, `warnings`) у консоль.

## Бібліотека шаблонів і змінні

- Сторінка "Шаблони" дозволяє завантажити власний DOCX-шаблон для кожного
  типу документа (договір/кошторис/рахунок/акт/комерційна пропозиція),
  активувати його (стає шаблоном за замовчуванням для цього типу) та
  перевірити, які змінні `{var}`/`{#loop}` в ньому використано.
- Кнопка "Перевірити переменні" викликає `/api/templates/:id/validate`:
  показує знайдені змінні/циклі, невідомі змінні (з підказкою "можливо, ви
  мали на увазі..." за відстанню Левенштейна) та рекомендовані для цього
  типу документа змінні, яких немає в шаблоні.
- Повний список системних змінних та полів циклів `{#materials}`/`{#works}`
  доступний через `/api/variables` (а також на сторінці "Шаблони").
- Якщо власний/активний шаблон не завантажено — використовується вбудований
  шаблон з `server/src/templates/*.docx`.

## Кастомні поля об'єкта

Окрім стандартних полів об'єкта, адміністратор може створити власні поля
(сторінка налаштувань кастомних полів): ключ (латиниця, напр.
`client_ipn`), підпис, групу (клієнт/об'єкт/оплата/документ/кошторис),
тип (текст/число/дата/чекбокс/select тощо), обов'язковість. Ці поля:

- автоматично з'являються на формі об'єкта, згруповані за `group_name`;
- зберігаються в `object_custom_field_values` (одне значення на пару
  об'єкт×поле);
- доступні в шаблонах документів як звичайні змінні `{key}` нарівні з
  системними;
- якщо позначені обов'язковими і не заповнені — генерація документа
  блокується з переліком незаповнених полів.

При створенні сидяться 10 типових полів (ІПН, ЄДРПОУ, юр. адреса,
директор, посада, банківські реквізити, кадастровий номер, підстава
документа, коментар до документа) — їх можна редагувати чи вимикати.

## Версіонування кошторисів

Кожне завантаження нового файлу кошторису для об'єкта створює новий запис
з інкрементальним `version`, попередні версії позначаються `is_active = 0`.
У картці перевірки кошторису є кнопка "Подивитися сирий текст" — показує
розпізнаний текст файлу для діагностики, якщо автоматичне розпізнавання
дало незадовільний результат. Завантажити інший файл можна на будь-якому
етапі (до і після підтвердження).

## Скачування файлів

Скачування документів і шаблонів виконується через авторизований
`fetch`-запит із заголовком `Authorization: Bearer <token>` (а не через
звичайне посилання `<a href>`) — інакше браузер не передає токен і API
повертає 401. Це реалізовано в `client/src/api.ts` (`downloadFile`).
